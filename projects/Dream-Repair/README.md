# Dream Repair

一款以绘制手势施放技能的休闲战斗游戏。玩家通过线切和闭合手势应对敌人与 Boss，并在关卡推进中获得成长与修复祝福。项目结合手势输入、即时战斗反馈和竖屏移动端 UI，适合展示从玩法交互到发布准备的独立开发经历。

**项目角色：独立开发，负责全部开发工作。项目状态：已过审（开发者提供）。**

## 个人贡献

- 负责核心玩法与程序实现，组织手势采样、几何识别、技能触发、敌人受击及关卡/Boss 流程；以时间和距离双阈值控制轨迹采样，结合轨迹平滑与点到线段距离实现线切判定。
- 负责 UI 与反馈表现、素材整合和移动端适配，将屏幕安全区转换为布局锚点，并处理 HUD、技能与战斗反馈的衔接。
- 负责调试及发布准备，维护场景构建、iOS Xcode 和 Android Studio 工程导出相关工具，整理图标、英文资料、官网与隐私页面；原项目包含 EditMode/PlayMode 测试。

## 推荐阅读顺序

1. [GestureInput.excerpt.cs](code/GestureInput.excerpt.cs)：`UpdateGestureInput` 和 `FinishGesture`。按距离与时间双阈值采点，松手后计算路径长度、包围盒和首尾距离，将输入分派到环形技能或线切技能。
2. [StrokeCollision.excerpt.cs](code/StrokeCollision.excerpt.cs)：`SmoothPoints`、`CastLineCut`、目标后备选择和点到线段距离。对输入点进行三点加权平滑，再以敌人半径加轨迹宽度进行逐段命中判断。
3. [SafeArea.excerpt.cs](code/SafeArea.excerpt.cs)：将 `Screen.safeArea` 的像素坐标归一化为锚点；安全区变化后更新子布局。
4. [SmokeFlow.excerpt.cs](tests/SmokeFlow.excerpt.cs)：原 PlayMode 冒烟测试，包含技能调用、HUD 断言和 Boss 关卡跳转。这里的测试通过辅助接口施放技能，不覆盖真实鼠标轨迹识别。

## 可以讲清楚的实现

- 距离阈值 `0.055f` 与采样间隔 `0.024f` 同时满足才增加中间点，结束时使用更小的 `0.025f` 补充末点。
- 闭合识别要求首尾距离小于 `0.42f`，包围盒宽高均不小于 `0.7f`，路径长度不小于 `1.8f`。它是几何启发式，不是通用手势分类器，也没有进行圆形拟合。
- 轨迹无直接命中时，当前实现会选择 Boss 或最近敌人作为后备目标。应把这个行为解释为明确的玩法容错，而不能描述成严格的轨迹碰撞命中。
- 点到线段距离通过投影参数截断到 `[0,1]`，并处理退化为单点的短线段。
- 当前碰撞查询遍历敌人和轨迹线段；点数为 P、敌人数为 E 时，最坏复杂度为 O(E×P)。没有空间索引或对象池实现。
