# 玩法特色与展示安排

作品集的一句话介绍：**旋转水道，引导需要的两种颜色汇合，并将第三种颜色挡在目标之外。**

这里展示的是该项目的机制组合和实现特点；没有进行竞品或行业首创性调查。

## 玩家做出什么决策

玩家面对红、蓝、黄三个光源，通过旋转直道、弯道和分叉水道改变连接关系。目标颜色为紫、绿或橙；让颜色到达目标的同时，还需要控制哪些颜色能进入。

以配置中的第 1 关为例，目标是紫色：红和蓝到达时满足要求；黄也到达就变成三色集合，目标无法完成。后续锁定石限制可旋转位置，滤色石只允许指定的基础颜色继续传播。

## 机制怎样映射到代码

| 玩家看到的变化 | 代码依据 |
| --- | --- |
| 旋转改变水道方向 | `PortsFor` 用四方向位和模 4 运算得到开口 |
| 两格之间连接或断开 | 当前格出口和相邻格反向入口同时存在才传播 |
| 多个颜色在同一水道汇合 | `AddMask` 用按位或累计颜色集合 |
| 滤色石阻止某些颜色 | `ApplyFilter` 用颜色掩码做按位与 |
| 第三种颜色污染目标 | `IsTargetLit` 要求 `actual == required` |
| 预览暂时显示答案 | `PreviewRoutine` 使用 `solutionRotation` 代替当前旋转值 |
| 亮光沿水槽显示 | `BuildChannelSegments` 将光段分成方块内和方块间的部分 |

| 颜色规则示例 | 位集合结果 |
| --- | --- |
| 红 `001` 与蓝 `010` 汇合 | `011`，对应紫色目标 |
| 再混入黄 `100` | `111`，不满足紫色目标 |
| 紫色集合经过蓝色滤石 | `011 & 010 = 010`，只剩蓝 |

这是关卡规则的离散表示，视觉颜色由 `UnityColor` 单独映射。

## 建议录制的 60 到 90 秒片段

先准备棋盘、干扰色错误、正确连接三张对照材料，具体构图与命名见[作品集截图清单](../../docs/SCREENSHOT_CHECKLIST.md)。

1. 先展示一个清楚的目标和三个光源，做一次旋转，让路径与颜色即时变化。
2. 展示一种“路径连通但颜色错误”的状态，解释为什么还不能完成目标。
3. 调整连接，排除第三色，让所需两色到达并触发完成反馈。
4. 展示带滤色石或锁定石的关卡，说明新增的决策约束。
5. 使用实际界面上的 Preview，展示短暂答案预览及返回当前状态。

这些是后续录屏建议，本目录没有生成录像或真机截图。演示时以当前可运行版本为准，不使用控制器中未接入界面的交换或撤销功能充当演示内容。

## 给技术面试官的阅读路线

先看 [LightPuzzleModel.cs](code/LightPuzzleModel.cs) 的 `PortsFor` 和 `IsTargetLit`，再回到 `SimulateSources` 理解传播。接着看 [BeamRenderer.cs](code/BeamRenderer.cs)，解释为何逻辑状态和可见光段要分别处理；最后看[已有测试节选](tests/LightRules.excerpt.cs)，说明准备覆盖的反例。

可以进一步讨论：环路中颜色位只增加为何有利于收敛；是否可以改成变化队列传播；目标精确匹配为什么比包含匹配更适合干扰色玩法；预置答案测试与自动求解证明有什么差别。
