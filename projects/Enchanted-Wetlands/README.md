## 推荐阅读顺序

1. [LevelData.cs](code/LevelData.cs)：完整原文件。关卡、方块旋转、预置答案、锁定、滤色、光源和目标的数据定义。
2. [LightPuzzleModel.cs](code/LightPuzzleModel.cs)：完整原文件。端口旋转、双向邻接检测、多源颜色传播、滤色与目标判断。
3. [BeamRenderer.cs](code/BeamRenderer.cs)：完整原文件。将逻辑光段拆成方块内、方块间的显示段；复用已有 UI 图元并定位辉光、核心与流动效果。
4. [PreviewFlow.excerpt.cs](code/PreviewFlow.excerpt.cs)：预览条件、消耗和协程。使用预置 `solutionRotation` 模拟并显示答案，约 1.35 秒后恢复当前棋盘显示。
5. [LightRules.excerpt.cs](tests/LightRules.excerpt.cs)：已有 EditMode 测试节选，覆盖通道分段、无效入口、预置答案和干扰色排除。本次整理没有执行这些测试。

## 从代码能说明的特色

- 红、蓝、黄分别用 `1`、`2`、`4` 表示。颜色汇合使用按位或，滤色使用按位与，目标要求实际颜色集合精确等于所需集合。
- 通道用四个方向位表示，旋转将方向按模 4 移位；相邻格的对应开口都连通才传播。
- 一次模拟先注入有效光源，然后反复传播新增颜色位，直到无变化或保护次数耗尽。每轮读取状态快照，避免边枚举边修改字典。
- 规则层只返回每格颜色和光段，渲染层负责坐标转换、颜色、宽度和动画；预览通过传入不同旋转读取函数复用同一模拟入口。
- 当前 JSON 实际包含 100 关、5 个章节；每关 3 个光源、1 个混色目标。45 关有滤色石、45 关有锁定石，这两组关卡可能重叠。这些是本次读取配置的统计，不是本次通关测试结果。

## 展示和验证边界

这是一套离散网格颜色规则，不是反射/折射物理模拟；颜色相加也不是 Shader 的颜色混合。代码包含端口连通和滤色传播，没有据此宣称实时光线追踪或自动生成关卡。

预览依赖预置解，不能称为实时自动求解；`UndoLastMove` 和 `BeginSwapTool` 虽存在于原控制器，但本次没有在主界面找到调用，因此不作为当前玩家功能展示。

`LightPuzzleModel` 的每轮扫描、字符串坐标键和字典快照会产生遍历及分配开销；渲染池只增不减，避免部分重建但不等于没有分配。本次未测量帧率、GC 或设备性能。

完整文件依赖 UnityEngine，`BeamRenderer` 还依赖 uGUI；预览节选依赖原控制器、`SaveManager`、UI 回调和资源。此处没有复制整个场景、关卡 JSON 或美术，也不是可直接启动的游戏工程。
