# Sushi Sprint Sorter

一款通过拖拽寿司、调整轨道完成分拣的休闲游戏。玩家在移动队列中选中目标并送往对应判定区，局外通过本地进度、商店购买和装备选择形成持续目标。项目适合展示移动端触摸交互、对象状态管理与进度持久化。

**项目角色：独立开发，负责全部开发工作。项目状态：已过审（开发者提供）。**

## 个人贡献

- 负责玩法设计、Unity/C# 开发、规则与数值配置、UI 表现、素材整合和调试交付，实现三轨道分拣、单对象拖拽和松手吸附。
- 将射线命中与屏幕距离容错结合，处理附近点击、多个候选目标和拖拽状态切换；拖拽时暂停对象纵向移动，并保留取消操作的原轨道。
- 实现本地钱包、物品所有权、购买、装备及 PlayerPrefs 保存，加载时检查装备 ID 和类别，对无效数据回退默认值。
- 配置交互与存档相关 PlayMode 测试，覆盖附近/远处点击、单对象移动、购买后重载和无效装备恢复；负责发布准备，并在历史记录中完成图文官网及隐私页面的自包含 HTML 整理。

## 推荐阅读顺序

1. [SorterLetter.cs](code/SorterLetter.cs)：完整原文件。对象持有自身拖拽状态，拖拽时停止纵向运动、抬高显示，松手后吸附到最近轨道；取消时回到先前轨道。
2. [DragInput.excerpt.cs](code/DragInput.excerpt.cs)：管理器输入、射线选中、附近对象选中与拖拽分派。它是原类方法节选，保留对相机、列表和高亮回调的引用。
3. [SorterProgressStore.cs](code/SorterProgressStore.cs)：完整原文件。管理本地钱包、已拥有物品、装备与 PlayerPrefs 持久化，加载时修复无效或分类不符的装备 ID。
4. [InteractionAndSave.excerpt.cs](tests/InteractionAndSave.excerpt.cs)：原 PlayMode 测试节选，覆盖单个对象拖拽、近处/远处点击、购买后重载、脏装备回退、暂停纵向运动及轨道吸附。

## 可以讲清楚的实现

- 先在有效物体的射线命中中选最近对象；射线没有选中时，在屏幕坐标中寻找容错半径内的对象。原管理器字段默认容错半径为 76 像素，字段定义未包含在节选中。
- 容错候选忽略相机后方对象；屏幕距离近似相同时，选择世界 Y 更大的对象作为分拣队列优先项。
- `SorterLetter.Update` 同时检查玩法状态与暂停状态。拖拽期间跳过纵向位移，但仍执行到达判定线的检查，不能把它描述为所有判定都停止。
- 使用 HashSet 保存所有权；购买时检查物品、所有权和余额，更新装备并保存。再次购买已拥有物品会转为装备，不会重复扣费。
- 默认装备不仅检查是否拥有，还检查商品定义和分类，避免读取不存在的角色或把轨道 ID 装到角色位置。

## 测试边界

测试节选依赖原测试夹具中的 `game`、`ProgressKeyPrefix`、场景加载与 UI；不是独立测试工程。本次没有执行这些测试，测试文件的存在不表示当前构建全部通过。

原有测试通过管理器测试入口驱动部分操作，可检查状态流，但不代替触摸硬件和不同 DPI 设备的交互验证。

## 当前实现的取舍

触摸容错使用固定像素值，不是 DPI 归一化；射线选中使用 `Physics.RaycastAll`，存在数组分配。PlayerPrefs 保存的是客户端本地进度，没有服务端校验、事务回滚或防篡改保证；每次进度变化调用 `Save` 的策略也可以讨论批处理时机。

完整 `SorterLetter.cs` 仍依赖原管理器和枚举，资源路径只作为字符串保留；本目录没有复制对应美术或场景。
